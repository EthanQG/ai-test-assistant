# 离线评测人工标注说明

当前`seed_v1.json`只包含3份完全虚构的种子需求，用于验证标注格式。它不是完整评测集，也不能用于宣称模型效果。

## 标注原则

- `facts`：需求原文明确表达的事实，不加入常识推测。
- `business_rules`：会改变业务结果的明确约束、阈值或状态规则。
- `risks`：可以从需求推导出的测试风险，必须写明推导依据。
- `clarification_questions`：缺少答案会改变测试预期的关键问题；实现细节不应标为阻塞项。
- `necessary_scenarios`：一份合格测试分析必须覆盖的核心、边界或异常场景。
- `forbidden_assertions`：原文没有依据、模型不应擅自补充的业务结论。

每条事实、规则、风险和必要场景都必须附带`evidence`。标注人无法指出依据时，该条目不能进入金标准。

## 人工复核流程

1. 第一位标注者阅读脱敏需求并完成六类标注。
2. 第二位复核者只依据同一份需求检查遗漏、错误推断和问题必要性。
3. 两人有分歧时保留分歧记录并人工裁决，不能让另一个LLM自动决定金标准。
4. 数据通过契约校验后才能进入正式评测集。

## 主观指标规则

测试点可执行性采用0～2分人工规则：

- 0分：缺少操作或预期结果，无法执行；
- 1分：可以理解，但前置条件、操作或预期结果存在明显歧义；
- 2分：前置条件清楚、步骤可执行、预期结果可判定。

该评分需要两人独立打分并记录分歧。当前种子集只定义规则，尚未产生真实评分数据。
